# 子流程画布的本地 H2 联调

日期：2026-10-14。使用独立的 H2 内存数据库和端口验证本轮页面；未修改本机 MySQL 数据。

## 环境

- 后端：`http://localhost:8081/`，Java 21、测试类路径中的 H2，应用运行期间保留内存数据。
- 前端：`http://localhost:8001/`，`RISK_API_TARGET=http://localhost:8081`。
- 演示标识：子流程 `uiEligibilityT5`、外层流程 `uiCheckoutT5`、场景 `uiCheckoutSceneT5`。数据只用于联调；H2 进程退出后消失。

## 页面路径与结果

1. 通过真实 API 创建并发布资格子流程 v1，声明输入 `positive`，条件真返回 `ELIGIBLE`，假返回 `NOT_ELIGIBLE`；外层草稿预置开始、未配置的 `SUBFLOW`、`RESULT`、结束节点。
2. 打开 `/flows/uiCheckoutT5/editor`，选择调用节点。页面列出已发布子流程及版本，禁止选择未发布的外层流程；选择 `uiEligibilityT5` 后显示固定版本 ID 1 和必需输入 `positive`。把该字段映射到外层请求的 `positive`，在页面保存草稿 r2、校验通过并发布外层 v1。
3. 创建场景并绑定外层流程。打开 `/scenes/uiCheckoutSceneT5/flow`，以 `{ "positive": true }` 试运行，页面显示外层版本 ID 2、运行 `SUCCEEDED`、外层结论 `FINAL`，以及调用节点 `call` 所用子流程版本 ID 1 与子流程结论 `ELIGIBLE`。
4. 以 `{}` 试运行，页面显示 `FAILED`、`FLOW_EXECUTION_FAILED`、调用节点 `call` 的失败状态和固定版本 ID，不显示正常外层结论。
5. 子流程发布 v2 后重新打开外层草稿，页面仍显示固定 ID 1，同时提示当前发布版本 ID 3；点击“升级到当前版本”后，画布配置改为 ID 3，原有同名输入映射 `positive` 保留。此升级只修改当前画布，未自动保存或发布。
6. 已保存的画布可直接离开；修改输入声明后离开会出现未保存提示，恢复到已保存内容后不再提示。

## 验证边界

此记录验证的是一条子流程的页面配置、发布和同步执行，以及版本更新提示。两条子流程组合、按子流程结果分支的后端行为已有集成测试；对应的完整营销模拟样板和订单反馈仍需后续迭代。浏览器使用的流程与场景名称由联调脚本提供，个别中文名称在该脚本编码下显示为问号；流程码、版本和业务行为不受影响，产品页面自身的中文控件显示正常。
