# 结算优惠营销闭环本地联调

日期：2026-10-14。后端使用 JDK 21、Spring Boot test profile 与 H2 MySQL 兼容模式，端口 8081；前端 Umi Max 端口 8001，`/api` 代理到 8081。真实浏览器访问 `/marketing-demo`。

## 验证结果

- 点击“运行 30 人固定样本”后，场景 `demoCheckoutScene`、资格与优惠两条子流程、外层流程均初始化；外层执行结果包含两个子流程版本 ID。
- 三组均为 10 名合格用户。对照组支付率 20%、人均贡献利润 6.00 元；低额券组 30%、7.50 元；高额券组 40%、4.80 元。低额券组的人均利润最高。
- 手动输入订单金额 120 元、优惠前毛利 30 元、已有优惠 3 元，执行决策后回传 `EXISTING`，页面显示实际券与推荐券分开、贡献利润 27.00 元；再回传 `REFUNDED`，页面显示利润 0.00 元。刷新页面后同一进程内数据仍可查询。
- 浏览器初次打开时 Ant Design 输出三条废弃属性警告，已将页面改为当前 `orientation`、`title` 和单独文字标签；重载后未再产生新的错误。
- HTTP 集成测试覆盖初始化、固定样本、报告、实际优惠回传、幂等事件、事件冲突、退款、非法金额与重复结算 ID 冲突。完整后端 `mvn test`：87 个测试通过；前端 `npm test`：23 个测试通过，`npm run typecheck` 和 `npm run build` 通过。

## 样板边界

订单、反馈事件、分组结果与预算使用额只在当前进程内保存；进程重启后清空。流程资产、发布版本、场景绑定仍保存在数据库。样本是预置行为数据，用于验证链路和指标口径，不构成真实营销效果估计。
