# 场景与流程隔离的本地页面联调

日期：2026-10-13。使用独立的 H2 内存数据库验证新版代码；未改变原有 `8000/8080` 服务或本机 MySQL 数据。

## 访问方式

- 新版前端：`http://localhost:8001/`
- 新版后端：`http://localhost:8081/`
- 前端 dev 代理由 `RISK_API_TARGET=http://localhost:8081` 指定。浏览器直接访问 `/flows`、`/scenes` 时使用正常的 HTML 请求。

H2 数据只在该后端进程运行期间保留；重新启动后需重建演示数据。

## 页面验证路径与结果

1. 在“流程资产”新建 `sharedRiskDemo`，进入画布载入示例模板，保存草稿 r1、校验并发布 v1。
2. 在“场景管理”新建 `checkoutSceneA`、`checkoutSceneB`，分别通过“绑定流程”选择 `sharedRiskDemo`。列表显示两个场景的入口流程相同，当前版本均为 v1。
3. 回到该独立流程画布，再保存草稿 r2、校验并发布 v2。场景列表仍显示 A、B 都是 v1。
4. 只重新绑定场景 A：列表显示 A 为 v2，B 仍为 v1。
5. 调用真实后端决策接口进一步核对：A 执行版本 ID 2，B 执行版本 ID 1；流程资产当前发布版本 ID 为 2。

前端测试、类型检查与构建通过；后端 52 项测试通过。本次页面联调验证的是 H2 环境。V4 迁移尚未在本机 MySQL 5.7 上实测，正式使用 MySQL 环境前需单独验证。
