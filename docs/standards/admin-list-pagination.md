# 后台列表分页约定

状态：已确认的项目约定。适用于场景管理及后续有列表查询的后台页面。

## 页面与交互

- 列表统一使用 Ant Design Table 的分页能力；没有表格的列表可使用 Ant Design Pagination。分页由后端完成，前端只展示当前页的 `records`，不得一次取全量数据再本地切片。
- 列表展示总条数、当前页和每页条数选择。默认每页 10 条，可选 10、20、50、100 条；页面数据量少时也保留分页控件，便于查看总数和切换每页条数。
- 翻页时携带当前搜索条件；提交新搜索条件或修改每页条数时回到第 1 页。创建、编辑或删除后刷新当前查询结果；如果删除导致当前页没有记录且仍有上一页，应回到上一页。
- 加载中展示组件的 loading 状态；查询失败显示错误，不把失败结果当作空列表。

## 接口与后端

- 请求统一使用从 1 开始的 `page` 和 `pageSize`；响应包含 `records`、`total`、`page`、`pageSize`，并放在项目统一的 `ApiResponse<T>` 中。`total` 是相同查询条件下的记录总数，不是当前页记录数。
- 后端校验 `page >= 1`、`1 <= pageSize <= 100`，使用数据库分页查询和独立计数查询；筛选条件、`isactive` 条件和排序必须在两次查询中保持一致。排序使用稳定的字段组合，避免翻页时记录重复或遗漏。
- 前端不依赖接口默认页大小，应显式传入 `page` 和 `pageSize`。分页参数和响应字段在不同后台列表中保持一致。

当前实现参见 `web/src/pages/scenes/index.tsx`、`web/src/services/scene.ts` 和 `SceneServiceImpl#search`。
