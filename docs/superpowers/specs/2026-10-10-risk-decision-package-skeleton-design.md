# 风控决策平台包结构设计

日期：2026-10-10  
状态：待审阅

## 目标与范围

建立 Java 21 项目的最小源码骨架，让后续决策、策略、规则、特征等能力各有明确归属。本阶段只创建 Maven 项目描述和 Java 包职责说明，不定义 API、接口、实体、策略格式、数据库表、Redis 键或运行逻辑。

架构参考为本地 `D:\dmp\risk-engine` 仓库的 `cc92398` 版本，采用其按能力划分的思路，不移植 Go 代码。

## 项目形式

- 单 Maven 模块，`groupId` 为 `com.dmp`，`artifactId` 为 `risk-control-decision`。
- Java 源码根包为 `com.dmp.riskdecision`，目标语言级别为 Java 21。
- 版本管理采用 Spring Boot 4.1 系列 BOM；本阶段不引入运行时依赖，因为尚无实现类。
- 暂不创建 Spring Boot 启动类。当前骨架的验收是包结构清楚、Maven 项目可以通过基础校验；可启动服务留到接口与执行流程设计之后。

## 包结构与职责

```text
src/main/java/com/dmp/riskdecision/
├── decision/       一次决策的请求、结果与执行入口
├── policy/         场景、策略集、版本及发布概念
├── orchestrator/   决策步骤的执行顺序、并行关系与结果聚合
├── rule/           规则定义与表达式求值
├── feature/        决策所需特征的获取与表达
├── list/           名单查询能力
├── model/          模型评分能力
├── audit/          决策轨迹与审计记录
└── shared/         经多个能力共同使用且语义稳定的基础类型
```

每个一级能力包只放一个 `package-info.java` 记录职责。将来某个能力确实需要接口、用例、领域对象或存储适配时，再在该能力包内建立 `api`、`application`、`domain`、`infrastructure` 子包。例如规则相关的持久化适配会位于 `rule.infrastructure`，不会集中放进全局 `mapper` 包。

`shared` 不承接业务逻辑，也不是各包临时类型的堆放处；只有确实跨能力复用的基础概念才进入该包。

## 依赖方向

本阶段没有代码依赖。后续设计遵循：外部接入和基础设施适配依赖能力内的应用与领域契约，领域规则不依赖 Spring、MyBatis、Redis 等框架。跨能力调用通过明确契约完成，避免包之间直接访问彼此的存储实现。

## 验收

1. `pom.xml` 声明 Java 21、项目坐标与 Spring Boot 4.1 系列版本管理。
2. 上述九个能力包存在，且每个包都有准确、简短的职责说明。
3. 项目没有业务接口、策略配置、数据库迁移脚本或占位执行逻辑。
4. Maven 基础校验通过。

## 后续设计议题

决策请求与结果契约、策略和步骤模型、规则 DSL、特征失败语义、MySQL 与 Redis 的职责、灰度及影子运行、审计可靠性，均在后续独立设计中确定。
