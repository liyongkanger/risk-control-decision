# 结算优惠营销演示闭环设计

日期：2026-10-14
状态：已选营销样板的实施设计；本轮使用可重建的模拟数据，不作为真实活动或 v0.1 产品范围扩张。

## 目标与边界

以[结算页优惠样板](../../../prd/scenarios/checkout-offer-incremental-profit.md)为事实源，提供一条可运行的“配置并发布决策 → 模拟结算 → 回传实际结果 → 比较人均贡献利润 → 调整版本再试”的路径。优惠资格与选择是独立发布的决策子流程，外层明确给出最终业务结果。演示结算系统只记录模拟用券、支付和退款，不连接真实商城或执行真实发券。

本轮在 `business.marketing` 中隔离样板用例；现有 `policy`、`decision` 和 LiteFlow 服务保持通用。模拟订单和反馈存在本应用实例的内存仓储中，重启后可用同一实验标识重建；流程资产及版本仍沿用现有数据库。演示数据不声明真实增量收益。

## 方案选择

选择**固定演示配置 + 真实决策引擎 + 内存反馈仓储**。固定图通过现有流程服务保存、校验、发布；批量演示对每位用户真实调用场景执行接口，再由模拟结算产生付款事件。内存仓储实现事件去重与退款修正，避免为模拟数据增加生产业务表及迁移。将来对接真实订单时，可替换模拟结算和仓储，保留决策版本、结果与反馈的关联契约。

## 决策样板

- `demoOfferEligibility`：输入 `eligible`，返回 `ELIGIBLE` 或 `INELIGIBLE`，并在明细中返回布尔 `eligible`。演示入口统一按订单金额满 100 元、优惠前贡献毛利减 18 元后不少于 10 元、活动预算仍可覆盖 18 元，计算三组共用的资格布尔值；子流程使此判断成为可追溯业务结论。
- `demoOfferSelection`：输入由资格结果映射来的 `eligible`、`inExperiment`、`highGroup`。无资格或对照组返回 `NO_NEW_OFFER`；其余分别返回 `LOW_VALUE_OFFER` 或 `HIGH_VALUE_OFFER`，明细和建议动作携带固定券码。
- `demoCheckoutDecision`：顺序调用上述两个子流程，读取选择子流程的结论，在自己的 `RESULT` 节点返回最终结论。外层发布版本固定两条子流程版本 ID；子流程后续发布不自动变更外层。
- `demoCheckoutScene`：绑定外层当前发布版本，供真实 `DecisionExecutionService` 同步执行。初始化重复调用时不重复创建或覆盖已有发布版本。

演示券配置：订单门槛 100 元、低额 5 元、高额 18 元、单笔高额券后贡献利润底线 10 元、活动新增券预算 2,000 元。它们只属于本样板，不进入平台通用决策枚举。

## 模拟结算与反馈状态

每次结算用 `experimentId + checkoutId` 唯一定位，记录匿名用户 ID、稳定实验组、请求 ID、场景及外层/子流程版本、推荐结论、已有优惠、实际优惠、支付及退款状态、优惠前贡献毛利和实际商家优惠成本。用户组由 `experimentId:userId` 的稳定哈希分配为 `CONTROL`、`LOW`、`HIGH`；同一用户在同一实验内不跨组。

`POST checkout` 创建一次真实决策记录，重复同 ID 且输入相同返回原记录，输入不同报冲突。`POST feedback` 接收唯一事件 ID：

- `SETTLED`：声明支付与否、实际应用的互斥优惠。可不用推荐券，也可改用原有优惠；未支付时实际优惠为 `NONE`。已结算订单不可用另一事件重复结算。
- `REFUNDED`：只针对已支付订单，修正本次贡献利润为零；订单和分组仍保留在统计样本中。

同一事件 ID 重放且内容一致时不重复计数；相同 ID 携带不同内容返回冲突。建议动作仅是决策结果，实际优惠成本只由 `SETTLED` 事件中的实际选择决定。支付订单贡献利润 = 优惠前贡献毛利 − 商家实际承担优惠；未支付或全额退款为零。金额使用 `BigDecimal`，不用浮点数计算。

## 固定演示数据与指标

`POST run-fixture` 为三个组各找 10 名稳定分组用户，每人一次结算。核心 30 人均满足资格、订单 120 元、优惠前贡献毛利 30 元且没有已有优惠。模拟支付人数按对照组 2、低额券组 3、高额券组 4 固定，付款者实际使用本组推荐券。相同实验 ID 再次运行不新增订单或反馈；换实验 ID 可在新发布策略下再次运行。

报告以同一实验中**符合资格且进入结算页的唯一用户**为分母，按组汇总支付用户、支付转化率、实际补贴、退款用户与人均贡献利润；同一用户多次结算时先按用户汇总利润。固定数据预期人均利润依次为 6、7.5、4.8 元，显示高额券组虽然转化率最高、利润却低于对照组。手动结算可覆盖已有优惠、未用推荐券、无资格及退款；这些记录按其实际资格纳入或排除主指标。

## 接口与页面

演示 API 位于 `/api/demo/checkout-offer`：`POST /setup`、`POST /checkout`、`POST /run-fixture`、`POST /feedback`、`GET /report?experimentId=`。所有响应沿用 `ApiResponse<T>`，参数错误、资源不存在与冲突沿用项目稳定结果码；详细字段以新增 `docs/api/marketing-demo.md` 和测试为准。

后台新增“营销闭环样板”页面，提供初始化、实验标识、运行固定样本、三组指标、逐笔决策/实际用券/支付/退款明细，以及手动结算和反馈。页面清楚标识“模拟数据”，外层结论、建议优惠与实际使用优惠分列展示。前端统一经 `web/src/services/` 解包接口响应；列表仅展示本次演示数据，未引入生产后台列表接口。

## 验收

1. 初始化后能在流程资产与场景页面看到两条子流程、一条外层流程及场景，并可按真实接口执行；重复初始化不生成多余版本。
2. 固定实验生成 30 次真实决策及模拟结算，报告展示 6、7.5、4.8 元人均贡献利润和 20%、30%、40% 支付转化率；重复运行结果不变。
3. 对照组保留已有优惠，新增券与已有优惠互斥；建议券未使用时不计建议金额，退款使利润归零；反馈事件重放不重复计数。
4. 子流程版本、外层版本及推荐原因可从结算记录追溯。正常 `NO_NEW_OFFER` 与运行失败分开；失败不自动生成正常业务结论。
5. 后端与前端测试通过；浏览器完成初始化、固定样本、手动反馈与退款路径。内存数据重启边界在页面与文档中明确。
