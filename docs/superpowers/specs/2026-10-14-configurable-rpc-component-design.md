# 可配置只读 RPC 节点第一版设计

> 历史方案：已由[变量中心直接重构设计](2026-10-15-variable-center-refactor-design.md)替代，所述 RPC 操作接口和 `http-json-get` 不再实现。

日期：2026-10-14。状态：用户已确认“平台能力可配置、营销场景作为验收样板”，本版先完成只读 HTTP JSON 查询及后台配置。

## 目标

管理员在后台登记一个已允许主机上的只读 HTTP GET 操作，并形成不可变操作版本。流程设计者在普通组件节点选择该操作的当前版本、把请求输入映射到查询参数；发布时固定操作版本。运行结果写入节点结果，后续 `equals-value` 等条件节点可读取，不为每个业务接口编写 Java 节点类。

## 边界

- 保留现有流程图外壳和 LiteFlow 编译机制；增加 `http-json-get` 注册组件及配置表单。
- 操作定义保存在数据库；更新生成新版本。已发布流程的节点配置保留旧操作版本 ID，不随操作更新漂移。发布新流程前需要显式选择当前操作版本。
- 配置含操作码、名称、固定 HTTPS/HTTP URL、超时和允许的查询参数名。节点配置只含操作码、操作版本 ID 和请求输入映射；不存任意 URL、凭据或表达式。
- 服务端只允许环境配置的目标主机；第一版本地允许 `localhost` 与 `127.0.0.1`。请求体为空，响应必须为 JSON 对象，大小受限。远端非 2xx、超时或非法响应使节点失败；不把失败当作条件 `false`。
- 发布检查组件配置、操作版本与当前发布版本一致、参数映射完整及请求字段声明。发布链验证跳过外部调用，仅校验 EL 加载；运行时才请求远端。
- 现有 `emit-value`、`is-positive`、`equals-value` 和营销样板行为不变。数据库查询、写操作、认证、重试和降级留待后续迭代。

## 接口与页面

`/api/rpc-operations` 提供创建、分页列表、详情、更新版本；响应沿用 `ApiResponse` 和后台列表分页约定。流程编辑器从平台组件目录获取可选组件，在选择 `http-json-get` 后的同一节点面板中完成操作登记、搜索、更新版本、参数映射和结果说明，不新增独立管理菜单。接口文档见 `docs/api/rpc-operations.md`。

## 验收

用本地 HTTP 假服务登记一个操作，配置流程 `HTTP 查询 → equals-value 判断返回字段 → RESULT`，校验、保存、发布、执行。更新操作后，旧流程继续使用原版本；草稿显式升级后可发布新流程版本。验证无效主机、参数缺失、超时或非 JSON 响应，以及原有营销测试。
