# Day 2｜2026-10-13：后台骨架与场景、流程解耦

## 开发计划

- 搭建后端服务骨架和后台管理页面，确定从零到一的代码风格、分层和数据库约定，为后续项目留下可复用的实践。
- 完成场景管理、流程资产管理与画布的基础链路，让已发布流程能够被场景引用和执行。

## 实际开发

- 初始化后台管理能力，补齐通用响应、异常处理、Lombok 数据对象及 LiteFlow 组件包的职责划分。
- 将“先建场景、再在场景内设计流程”调整为独立流程资产：流程保存、校验和发布后，由场景绑定指定版本。同一流程可供多个场景使用。
- 用两个场景绑定同一流程进行页面联调：流程发布 v2 后，两个场景仍运行各自绑定的 v1；仅重绑场景 A 后，A 使用 v2，B 保持 v1。
- 在本机 MySQL 5.7.40 上验证初版场景创建、流程发布、决策执行和重启后的数据保留。

## 问题与解决

- **场景和流程耦合，流程不能复用。** 将流程改为独立资产，场景只选择已发布版本；发布新版本不自动切换既有场景绑定。
- **前端组件配置难以准确描述，前后端协作边界不清。** 先用独立的图数据契约和后台页面跑通基础链路；组件配置体验与交接方式列为后续优化点。
- **本地验证环境有限。** H2 联调验证了 V4 的场景流程隔离；MySQL 联调覆盖到 V3。V4 尚未在本机 MySQL 5.7 实测，不能把两次验证混为一谈。
