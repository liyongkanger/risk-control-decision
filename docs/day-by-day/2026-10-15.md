# Day 4｜2026-10-15：组件拆分与变量中心初版

## 开发计划

- 继续区分组件类型、可复用组件定义和流程中的节点实例，明确“组件通用化”的边界。
- 将 RPC、HTTP 等取值能力收敛到变量中心，让流程更多关注“需要哪个业务变量”。

## 实际开发

- 建立变量中心初版，支持定义变量的名称、类型、来源与不可变版本；取值来源先覆盖受限 HTTP GET。
- 流程画布改为通过“获取变量”节点取值，并可由后续比较节点使用。旧 RPC 操作接口与 `http-json-get` 节点退出当前链路。
- 使用营销样板报告创建 `lowGroupUsers` 变量，试取值得到 10；发布“获取变量 → 比较变量 → 业务结果”的流程，实测返回 `SUCCEEDED / ENOUGH`。

## 问题与解决

- **组件直接承载外部调用配置会让流程节点绑定具体来源。** 将业务变量的取值配置放在变量中心，流程引用固定变量版本。
- **变量值有不同来源，单靠节点 JSON 难以统一。** 先明确变量名称、类型和来源的归属；请求输入、上游节点结果和外部取值的统一解析留到次日完善。
- **旧接口与新模型可能混用。** 移除旧 RPC API，并验证旧路径返回 404；变量来源失败时转成明确的取值错误。
