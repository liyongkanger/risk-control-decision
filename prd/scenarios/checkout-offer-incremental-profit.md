# 营销样板场景：结算页优惠选择与增量利润闭环

日期：2026-10-14  
状态：已选定的可运行样板场景；业务数据与结算系统均使用模拟实现。本文固定跨迭代的业务路径和验收口径，具体接口、存储及页面设计由对应迭代另行确定。

## 1. 场景目标与边界

用户进入结算页时，平台回答“本次是否推荐新增优惠；若推荐，选择哪一档”。样板的首要目标是提高**增量贡献利润**，同时观察支付转化、优惠成本和退款情况。平台返回决策及原因；模拟结算系统负责展示、应用优惠和产生后续事件。

本场景用于检验通用决策平台的能力，不代表已对接真实商城，也不把模拟实验的结果当作真实业务效果。当前没有可用历史订单数据，因此首轮先采用可解释的资格与利润保护规则，通过实验数据逐步学习两档券的效果，不预设个性化收益预测模型。

## 2. 已确定的业务选择

| 事项 | 样板约定 |
| --- | --- |
| 决策时点 | 用户进入结算页，模拟结算系统发起一次决策请求。 |
| 基线 | 不新增优惠时，用户仍可使用原有权益；对照组保持原有结算体验。 |
| 新增优惠 | 候选为低额固定金额券和高额固定金额券，均与已有优惠互斥。券额、门槛和有效期是样板配置，不写死为平台通用规则。 |
| 实验 | 按用户稳定分入对照组、低额券组或高额券组；同一用户在一次实验中不跨组。三组采用相同的资格条件。 |
| 利润数据 | 模拟订单可提供支付、退款、订单优惠前贡献毛利和商家承担的优惠额。 |
| 执行边界 | 决策推荐与最终实际使用优惠分别记录。未支付、未使用推荐券、改用已有优惠和退款都是有效结果。 |
| 复用 | “优惠资格”与“优惠选择”作为独立决策子流程；结算场景的外层流程明确产生最终业务结果。 |

## 3. 业务闭环

```text
设定增量利润目标与成本约束
  → 配置资格、两档券及外层结果策略
  → 用模拟样例测试并发布流程版本
  → 用户进入结算页，确定稳定实验分组
  → 资格子流程 → 优惠选择子流程 → 外层最终结论
  → 模拟结算系统展示并应用优惠
  → 回传支付、实际优惠、退款和贡献利润
  → 按实验组比较效果，定位决策与实际执行差异
  → 修改规则、重新测试并发布新版本
```

“对照组不新增优惠”和“资格不通过”都是正常业务结论；流程运行失败须单独表示，不能归为“不发券”。建议使用某张券也不表示券已经发出或被使用。

## 4. 决策路径与职责

1. 模拟结算系统提供用户标识、结算单标识、订单金额、优惠前贡献毛利、已有优惠和实验组。实验分组在模拟系统中稳定生成；v0.1 不要求平台内建实验分流。
2. **优惠资格子流程**检查活动参与条件、券使用门槛、订单利润底线等可解释规则，返回是否有资格及原因。资格规则对三组一致；不能只对实验组筛选后再与全部对照组比较。
3. **优惠选择子流程**根据实验组和资格结果，返回“不新增优惠”“低额券”或“高额券”的建议及原因。对照组始终不新增优惠；实验组不满足资格时也不新增优惠。利润底线和活动预算限制优先于推荐券。
4. **外层结算决策流程**显式产生最终业务结论、原因和建议优惠，保留两个子流程的结果与实际版本。它不会自动沿用最后一个子流程的结论。
5. 模拟结算系统决定实际应用哪项互斥优惠，产生支付或未支付及可能的退款事件。决策记录和执行记录通过请求标识、结算单标识关联。

以上描述业务行为；节点类型、字段校验、接口路径及持久化结构在实施设计中确定。

## 5. 样板数据与可运行用例

模拟数据至少覆盖以下输入与结果。金额均由样板配置提供，不代表真实商家的定价；测试用例应使用固定配置和固定随机种子，保证可重复运行。

供首次演示使用的一组**固定模拟参数**：两档券均满 100 元可用，低额券减 5 元，高额券减 18 元；应用新增券后单笔预计贡献利润至少为 10 元，活动新增券预算为 2,000 元。这些数字只定义演示输入，可在后续迭代中由有版本的样板配置替换。已有优惠与新增券互斥，实际优惠成本只按结算时选中的一项计算。

| 用例 | 条件 | 期望的业务结果或反馈 |
| --- | --- | --- |
| 对照组有原优惠 | 满足资格，已有可用优惠 | 不新增券；原优惠保持可用，记录基线优惠及后续订单结果。 |
| 低额券组 | 满足资格和利润底线 | 推荐低额券，返回原因；记录实际是否使用。 |
| 高额券组 | 满足资格和利润底线 | 推荐高额券，返回原因；记录实际是否使用。 |
| 不满足资格 | 任一组均可出现 | 正常返回不新增优惠及明确原因。 |
| 利润或预算约束不满足 | 原本可推荐券 | 不新增优惠，指出约束原因。 |
| 推荐未使用 | 返回新增券，用户使用原有优惠或放弃优惠 | 保留原推荐，同时记录实际优惠，不能把推荐金额当成实际成本。 |
| 未支付或退款 | 曾获得推荐 | 记录零支付或退款后的最终贡献利润；不删除该次实验样本。 |
| 子流程执行失败 | 任一子流程失败 | 外层运行失败，定位调用节点及版本，不返回正常优惠结论。 |

模拟数据需要至少两名用户分别触发重复结算，以验证稳定分组和事件去重；还要包含低额券提高利润、高额券增加转化却降低利润的可解释样例。模拟结果用于展示分析链路，不用于声称真实增量收益。

例如，演示数据可为每组设置 10 位符合资格的用户，订单优惠前贡献毛利均为 30 元，且这组用户没有已有优惠。对照组 2 人支付、低额券组 3 人支付、高额券组 4 人支付，均不退款且支付者实际使用推荐券。汇总结果分别为：对照组人均贡献利润 6 元、低额券组 7.5 元、高额券组 4.8 元；支付转化率依次为 20%、30%、40%。这组固定数据说明为什么不能只按转化率选择高额券。实际模拟数据还须包含上表中的已有优惠、未用券、退款和失败用例。

## 6. 记录与衡量

每次决策至少能关联：请求标识、匿名化用户标识、结算单标识、实验标识与分组、决策时间、外层及子流程版本、资格结果、推荐优惠及原因、已有优惠、实际应用优惠、支付与退款状态、优惠前贡献毛利、商家实际承担的优惠额。反馈事件应按结算单及事件标识去重，并允许退款修正原订单结果。

样板中的**订单贡献利润**定义为：已完成订单的优惠前贡献毛利，减去商家实际承担的优惠额，再按退款冲回；未支付订单为零。优惠前贡献毛利已扣除商品成本和约定的可变成本，计算时不得重复扣减。实际业务若存在其他补贴承担方，需要在接入时重新核对口径。

**主指标**是同一观察窗口内，每位符合资格且进入结算页用户的平均贡献利润。按用户稳定分组，以用户为比较单位，计入未支付用户的零利润，并汇总其窗口内符合条件的结算订单。分别比较低额券组、高额券组与对照组的差值；观察窗口、分流比例、优惠金额、预算和最小样本量在实施实验前作为配置确认。辅助指标为支付转化率、商家优惠成本、人均订单数、退款率及推荐券实际使用率。

对照组比较用于估计新增优惠带来的增量效果。样板的少量模拟数据只验证计算与展示是否正确；不能由此推断真实用户中的因果效果或推广收益。

## 7. 与产品迭代的关系

| 阶段 | 本场景中可验证的能力 |
| --- | --- |
| 当前基础 | 独立流程资产、场景绑定、草稿与版本、现有结构化流程执行。尚无显式营销结论。 |
| v0.1 决策子流程 | 独立发布资格与选择子流程；外层引用固定版本，显式返回“不新增优惠／低额券／高额券”、原因和建议；测试及追溯所用版本。模拟输入可携带实验组。只返回建议，不执行发券。 |
| 后续执行与反馈 | 模拟结算系统应用互斥优惠并回传结果；平台关联决策、执行与订单反馈，展示实验组指标并支持调整策略。具体版本和实施范围另定。 |

## 8. 后续迭代的共同验收依据

- 同一套流程能力能够发布资格与选择两个子流程，并由外层流程组合成结算页的最终结论；各子流程结果和版本可追溯。
- 正常“不新增优惠”、流程失败、推荐券、实际用券和最终利润在接口与页面上能分别辨认。
- 对照组保留原有优惠；新增券与已有优惠互斥；三组资格条件一致且用户分组稳定。
- 模拟订单支付、未支付、改用原优惠和退款都能关联回原决策；重复反馈不重复计入。
- 汇总展示三组人均贡献利润及辅助指标，能解释“高额券提高转化但降低利润”的样例结果。

## 9. 尚未确定的业务参数

低额券和高额券的金额、使用门槛、活动预算、单笔利润底线、分流比例、观察窗口、真实结算系统的优惠裁决规则，以及真实利润字段口径均待具体业务接入时确认。模拟实现可选择明确标注的固定示例值，但这些值不能升级为平台默认业务规则。
