# 通用决策平台能力地图

状态：产品方向讨论中；下表的六个能力区与“风控、营销共用产品闭环”的方向已确认。各能力的具体范围和迭代顺序尚未确定。

## 产品主线

定义决策目标 → 配置策略 → 测试模拟 → 发布 → 观察结果 → 调整策略。

```text
定义决策目标 → 配置策略 → 测试模拟 → 发布 → 决策追溯 → 效果反馈
                   ▲                                  │
                   └──────── 根据结果调整策略 ──────────┘
```

风控和营销共用这条工作过程，但各自的策略内容、决策结果和衡量指标可以不同。

## 能力区

| 能力区 | 用户要完成的事 | 风控例子 | 营销例子 |
| --- | --- | --- | --- |
| 决策定义 | 说明何时决策、目标是什么、可能返回什么 | 判断交易是否放行 | 判断用户适合哪种优惠 |
| 策略设计 | 组合数据、规则、模型与分支 | 名单、交易特征、风险评分 | 用户分群、资格规则、转化评分 |
| 测试模拟 | 用样例或历史数据预看新策略的影响 | 拦截率与误拦变化 | 覆盖人数与预计成本 |
| 发布管理 | 审核、灰度、回退策略版本 | 小流量试新拦截策略 | 分组试新优惠策略 |
| 决策追溯 | 查一次决策的结果及原因 | 为什么拦截这笔交易 | 为什么给这个用户优惠 |
| 效果反馈 | 把后续真实结果关联回决策，推动调整 | 确认欺诈、申诉结果 | 领取、使用、转化结果 |

效果反馈通常晚于决策发生；产品需要能关联当时的决策与后续的真实结果，才能支持持续调整策略。这里描述产品能力，尚未约定数据接入方式。

## 已明确的产品方向

- 平台面向通用决策，不限于风控；风控和营销用于检验能力是否可复用。
- 策略中的业务能力通过可配置的节点组件接入，具体业务逻辑由节点调用的能力实现。
- 产品同时保留“返回决策结果”和“由节点执行业务动作”两种能力；首轮先完成前者。一次决策应能明确区分策略结论、建议动作，以及已实际执行的动作与其结果。
- 首轮支持把独立发布的决策流程作为外层决策流程中的节点调用，限定为“外层 → 子流程”一层；多个子流程参与判断时，由外层显式决定最终业务结果。首轮草案见 [v0.1 决策子流程 PRD](../iterations/2026-10-v0.1-decision-subflow/prd.md)。
- 决策子流程独立于业务场景管理，可被多个场景复用；外层已发布版本固定引用指定的子流程发布版本，不随子流程后续发布自动变化。
- 决策结果具有统一基本信息，业务结论、业务明细由各流程定义；运行失败与正常业务拒绝分开表达，建议动作不等于已执行动作。
- v0.1 子流程运行失败时外层整体失败，不自动给出正常业务结论；故障分支和兜底能力安排到后续迭代讨论。
