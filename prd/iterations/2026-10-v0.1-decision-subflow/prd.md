# v0.1 决策子流程 PRD

日期：2026-10-13

状态：核心产品边界已确认；营销模拟样板已选，真实业务样板与部分交互细节待补充

版本：v0.1（产品迭代标识，非已发布版本）

## 本轮已确认的产品决定

- 平台面向通用决策，风控与营销都应能够使用同一套流程能力。
- v0.1 首先返回业务决策结果；由节点直接执行业务动作是后续能力。
- 决策子流程独立于场景管理，可被多个场景复用；它在外层画布中以可编排节点的形式出现。
- 一条外层决策流程可调用多个子流程，最终业务结果由外层显式决定。
- v0.1 只支持一层“外层 → 子流程”，不允许子流程继续调用子流程。
- 外层发布版本固定引用指定的子流程发布版本，子流程后续发布不会自动改变外层已发布版本。
- 决策结果采用统一基本信息，业务结论与业务明细由各决策流程定义；运行状态、业务结论、建议动作和已执行动作是不同概念。
- 外层调用子流程时显式对应输入字段；子流程只接收对应后的输入，其结果归属调用节点，不直接读写外层的全部运行数据。
- v0.1 中任一子流程运行失败都会使外层整次运行失败，不生成正常业务结论；故障分支与兜底业务结论留待后续迭代。

## 1. 背景与目标

平台面向风控、营销等不同业务。一个业务场景可能需要多个相对独立的判断：例如交易准入与欺诈判断，或营销资格与优惠选择。当前平台已有场景流程编辑与运行基础，但尚未将“业务决策结果”明确为产品输出，也不能在一条流程中复用另一条已发布的决策流程。

本轮目标是让用户创建可独立发布的**决策子流程**，在一条**外层决策流程**中把它作为节点调用，并由外层显式产出最终业务结果。流程运行成功与业务决策结论须分别呈现。

```text
业务请求 ──► 外层决策流程
                  │
                  ├──► 决策节点 A ──► 已发布子流程 A ──► 结果 A ──┐
                  │                                               │
                  └──► 决策节点 B ──► 已发布子流程 B ──► 结果 B ──┤
                                                                  ▼
                                                        外层组合判断
                                                                  │
                                                                  ▼
                                                外层配置的最终业务结果
```

图中两个子流程仅用于说明一条外层流程可组合多个判断，并不表示所有路径都必须执行两个子流程。最终结果由外层配置，不能自动取最后一个子流程的结果。

## 2. 用户与典型场景

| 用户 | 需求 |
| --- | --- |
| 策略设计者 | 把可复用的判断封装为子流程，在不同场景中调用并观察其输出。 |
| 业务负责人 | 明确外层流程如何综合多个判断，查看最终结论和原因。 |
| 测试与运营人员 | 使用样例验证每个子流程及外层组合的结果，并追溯一次决策经过了哪些流程版本。 |

**风控样例：**交易流程先调用“准入决策”和“欺诈决策”。准入不通过或欺诈风险高时，外层给出“拒绝”；需要人工判断时给出“人工审核”；其他情况给出“放行”。这三个最终结果由外层策略明确配置。

**营销样例：**营销流程调用“优惠资格决策”和“优惠选择决策”。外层根据两者的结果明确返回“无优惠”或某个优惠方案。本轮只返回结果，不直接发券。

结算页优惠选择已选为跨迭代的可运行模拟样板，业务路径和效果口径见[营销样板场景](../../scenarios/checkout-offer-incremental-profit.md)。该文档中的实验反馈与优惠执行属于后续能力，不扩大本轮交付范围。

## 3. 产品概念

| 概念 | 定义 |
| --- | --- |
| 决策流程 | 回答一个明确业务问题的可发布流程，运行后返回业务结论及原因。 |
| 决策子流程 | 被另一条决策流程引用的决策流程；可以独立设计、测试和发布。 |
| 决策节点 | 外层画布上调用决策子流程的节点。它在编辑体验上属于可编排组件，但引用对象、输入输出和版本需明确展示。 |
| 条件节点 | 根据已有值选择后续路径的节点；它本身不代表完整的业务决策。 |
| 结果配置 | 流程中明确指定某条执行路径应产出的业务结论及原因；外层的最终业务结果由外层自己的结果配置决定。 |
| 最终业务结果 | 外层流程对本次业务问题给出的结论，由外层显式定义；不能把最后一个子流程的结果自动当成最终结果。 |
| 建议动作 | 决策结果给调用方的后续处理建议；它不表示动作已经发生。 |
| 执行流程 | 将来用于推进业务步骤、调用决策流程并可能执行业务动作的流程；本轮不建设。 |

决策子流程是可独立管理的流程资产，不必绑定一个独立业务场景。同一条子流程可以被多个外层场景引用；场景负责选择入口流程。

未来引入执行流程时，执行流程可以把已经发布的决策流程作为节点调用，再按其结论继续业务步骤。本轮外层本身仍是决策流程，只返回结果；不会因为预留执行流程而提前承担业务动作。决策结论与动作执行结果在产品上分别呈现。

## 4. 本轮范围

### 4.1 定义与复用决策子流程

1. 用户可以独立创建、命名、编辑、测试和发布决策流程，并说明它要回答的业务问题。
2. 每条决策流程声明所需输入和可能产生的业务结果。结果至少包含业务结论、原因；可附带供外层使用的明细值。不同业务自行定义结论取值，平台不强制使用风控专属的“放行／拒绝”。
3. 在外层决策流程中，用户可以添加决策节点，选择已发布的决策子流程，并为该节点配置输入对应关系。子流程只接收显式对应后的输入，不能隐式读取外层全部运行数据；它返回的结果保存在该调用节点名下，供外层的条件、规则及最终结果使用。
4. 一条外层流程可包含多个决策节点，按已设计的路径执行。v0.1 只支持一层“外层流程 → 决策子流程”；被引用的子流程不能再引用其他决策子流程。

### 4.2 显式产出最终结果

1. 外层流程必须定义最终业务结果，不能仅以“流程执行成功”或“最后一个节点的输出”代替。
2. 外层可以结合多个子流程结果、普通组件结果及条件分支决定最终结果。每条允许执行的结束路径都必须明确产出一个最终业务结果；没有结果或结果不确定时不得发布。
3. 对调用方展示最终业务结果、原因、请求标识和所用外层流程版本。子流程的结果与版本可在决策详情中查看，但不会自动覆盖外层最终结果。

#### 统一结果信息

每条决策流程，包括独立运行的子流程和外层流程，都按相同的产品形态呈现结果：

| 信息 | 含义与边界 |
| --- | --- |
| 请求标识、流程及版本 | 说明这是哪次请求、由哪个已发布版本得出，便于回看。 |
| 运行状态 | 说明流程是否完成。运行失败时不得伪装为“拒绝”“无优惠”等正常业务结论。 |
| 业务结论 | 流程回答其业务问题的结果；由该流程声明可用结论，例如风控的“放行／拒绝”或营销的“优惠 A／无优惠”。平台不预设跨业务的固定结论枚举。 |
| 原因 | 解释产生该结论的业务原因，便于调用方处理和人员追溯。 |
| 业务明细 | 根据流程需要提供额外结果，例如风险分、优惠方案；其含义由流程定义，不要求各场景完全相同。 |
| 建议动作 | 可选的后续处理建议；首轮只返回建议，不表示已经执行。 |

外层流程可以读取子流程的业务结论与明细来决定自身结果，但对子流程结果的引用应明确；两者的结论在决策详情中分别展示。未来加入动作节点后，再单独展示动作是否执行及其结果。

### 4.3 测试、发布与追溯

```text
发布外层版本
    │
    ├── 固定引用子流程的指定发布版本
    └── 校验输入对应关系、引用层级和每条结束路径的最终结果

运行外层版本
    │
    ├── 子流程正常返回 ──► 外层按配置产出业务结论
    │                       └── “拒绝”“无优惠”也属于正常业务结论
    │
    └── 任一子流程运行失败 ──► 外层整体运行失败
                              └── 不产出正常业务结论，保留失败位置供追溯
```

1. 用户可以为子流程和外层流程分别输入测试样例，查看业务结果、每个决策节点的输入与输出、失败位置及执行轨迹。
2. 外层发布时检查所引用子流程已有可用的发布版本、输入输出对应关系完整，以及每条结束路径的最终业务结果明确。被引用的子流程含有决策节点时阻止发布；直接或间接循环引用同样不得通过校验。
3. 外层发布版本固定引用当时选定的子流程发布版本。子流程以后发布新版本，不改变已发布外层流程的行为；外层需显式更新引用并重新发布。
4. 决策详情可按一次请求追溯外层流程及各子流程的版本、业务结论、原因和执行状态，区分“流程运行失败”和“业务结论为拒绝／无优惠”。
5. 子流程运行失败时，外层终止并返回运行失败；决策详情保留失败的子流程和调用节点位置，不产生“拒绝”“无优惠”等正常业务结论。v0.1 不提供在画布中配置故障分支或兜底业务结论的能力。

## 5. 用户操作路径

```text
定义业务问题与输出
  → 创建并发布一个或多个决策子流程
  → 在外层流程添加决策节点，选择子流程并对应输入输出
  → 配置外层如何产生最终业务结果
  → 用样例测试外层与子流程
  → 校验、发布外层流程
  → 调用外层流程并查看最终结果及决策详情
```

## 6. 验收口径

1. 可以分别发布两个独立决策子流程，并在同一条外层流程中调用；两者的结果都能被外层后续节点使用。
2. 同一条已发布的决策子流程可被两个不同业务场景引用，不要求为每个场景复制一份子流程。
3. 两个调用节点引用同一子流程并传入不同字段时，各自只获得映射后的输入，结果分别归属对应调用节点，不互相覆盖，也不修改外层其他节点的结果。
4. 外层最终结果与子流程结果可以不同，且由外层配置决定。例如子流程返回“需复核”，外层最终返回“人工审核”；页面与调用结果均不把二者混淆。
5. 外层存在未配置的最终结果路径、未发布的子流程、不完整的输入对应关系或循环引用时，校验给出可定位的问题并阻止发布。
6. 尝试引用一条已包含决策节点的子流程时，校验明确提示 v0.1 仅支持一层引用，并阻止发布。
7. 子流程发布新版本后，已发布的外层版本仍按原引用运行；测试和决策详情能看到实际使用的版本。
8. 风控样例和营销样例都能用相同的产品操作完成创建、测试、发布和结果追溯，且营销结果不需要套用风控枚举。
9. 本轮所有调用只返回业务决策结果及建议，不触发冻结账户、发券等业务动作。
10. 风控流程正常返回“拒绝”与流程运行失败在调用结果和决策详情中可明确区分；建议动作不会显示为已执行动作。
11. 任一子流程运行失败时，外层返回运行失败并能定位失败的调用节点；不会继续产出正常最终业务结果。

## 7. 本轮不包含

- 执行业务动作的节点及其动作结果管理。
- 将外层流程作为异步业务执行流程运行。
- 历史数据批量回测、效果反馈和长期指标看板。这些仍属于产品能力地图中的后续能力。
- 子流程再次调用子流程的多层嵌套；该能力留待后续迭代评审。
- 子流程失败后的故障分支、跳过执行或兜底业务结论；后续迭代再确定哪些场景需要及如何配置。

## 8. 待评审问题

1. 编辑外层草稿时，是否提示所引用的子流程已有新发布版本，以及是否提供显式升级操作？
2. 风控和营销的首批真实样板场景、业务结果取值及衡量指标需要业务方确认；表中的案例用于验证通用性，不代替业务需求。

## 9. 后续讨论入口

后续需要用具体业务场景检验子流程复用、结果表达和外层合并方式。当前候选为风控的“交易准入＋欺诈判断”及营销的“优惠资格＋优惠选择”；它们只是讨论示例，尚未确定为首轮交付场景。本轮先不细化其规则、字段、指标或页面交互，待选择真实样板场景时再继续。
