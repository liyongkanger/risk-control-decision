# 产品需求文档

本目录记录通用决策平台的产品定位、能力地图、路线图和各轮产品需求。风控与营销用于检验通用能力。这里描述用户目标、产品行为和衡量方式；具体技术设计放在 `docs/`。

## 一图看懂产品规划

```text
产品定位：通用决策平台
        │
        ▼
完整产品闭环：定义目标 → 设计策略 → 测试模拟 → 发布 → 追溯决策 → 反馈效果
        │
        ▼
路线图：先解决什么问题
        │
        ├── v0.1 决策子流程与明确业务结果      ← 已建立 PRD，尚未发布
        │
        ├── 子流程失败策略                    ← 后续候选，未排期
        ├── 执行流程与动作节点                ← 后续候选，未排期
        └── 效果观察与策略优化                ← 后续候选，未排期
```

后续候选之间尚未确定版本、时间或实施顺序。v0.1 的交付边界以[本轮 PRD](iterations/2026-10-v0.1-decision-subflow/prd.md)为准，完整能力见[能力地图](product/capability-map.md)。

## 目录划分

| 目录 | 作用 |
| --- | --- |
| `product/` | 持续维护整体产品方向：[产品定位](product/vision.md)说明服务对象与目标，[能力地图](product/capability-map.md)说明完整产品闭环。 |
| `roadmap/` | [产品路线图](roadmap/roadmap.md)记录迭代顺序、当前承诺与未排期候选能力。 |
| `iterations/` | 每轮迭代单独建目录，保存目标、范围、产品需求和验收口径。当前为 [2026-10 · v0.1 决策子流程](iterations/2026-10-v0.1-decision-subflow/prd.md)。 |
| `scenarios/` | 保存跨迭代复用的业务样板。当前为[结算页优惠选择与增量利润闭环](scenarios/checkout-offer-incremental-profit.md)，使用模拟业务数据。 |

## 迭代命名

迭代目录使用 `YYYY-MM-vX.Y-主题`，例如当前的 `2026-10-v0.1-decision-subflow/`。日期表示计划启动月份，版本表示产品迭代版本；实际发布日期在迭代文档中记录，不通过改目录名追踪。需求变更保留在所属迭代目录，并注明状态和更新日期。

产品能力地图是跨版本的当前视图；某轮承诺交付的范围以对应 `iterations/` 文档为准。未达成共识的产品问题明确标为“待讨论”，不写成既定需求。

## 文档维护

- 新的长期产品方向先更新 `product/`，再决定是否进入路线图；只有明确了版本与范围，才在 `iterations/` 下创建新目录。
- 每轮迭代的 PRD 写明目标用户、业务问题、产品范围、验收口径和待评审问题。未确认的示例场景标为候选，不当作交付承诺。
- `prd/README.md` 是唯一的目录说明文档；子目录放实际产品内容，不再各自维护 README。
